# The automorphism-orbit test against T_16 — board-wide, calibrated, negative

2026-09-17. Tools: `aut_orbit.py`, `orbit_probe.py`, `ac_ball_probe_v1.c`, `ac_shared_ball_v2.c`.

## The question

AC-triviality is invariant under `Aut(F_2)` applied to both relators (lemma and
proof-by-transport in `wh_lift.py`). `T_16` is the **complete** set of AC-trivial
pairs of total length ≤ 16: **129,247,304** states, closed, independently
reproduced twice today by two different engines. So for an unsolved row the
question stops being

> can AC moves get from this pair to `(x,y)`? — budget-bound, hopeless

and becomes

> does the **automorphism orbit** of this pair touch `T_16` anywhere?

Automorphism moves are not AC moves. They rewrite the presentation globally and
reach states no AC forward search sees at any feasible budget.

## What was run

| | |
|---|---|
| rows | 2,672 unsolved |
| orbit BFS bound | total length ≤ 20 |
| orbit elements tested | **182,160** (all of length ≤ 16) |
| ball | `T_16`, complete, 129,247,304 states, depth 101 |
| positive controls | 25 pairs AC-trivial **by construction** |

## Result

```
controls_hit = 25/25     orbit_hits = 0     resolved = 182,185/182,185
```

**Zero.** No unsolved row has a length-≤16 automorphism-orbit element that is
AC-trivial.

The positive controls are the whole reason this is worth recording. Every one of
the 25 was found at depth 0, immediately. So the zero is a statement about the
mathematics, not a broken harness — the distinction that makes a negative result
worth anything.

## What this does and does not prove

**Does:** within a length-20 orbit BFS, no unsolved row reaches an AC-trivial
pair of length ≤ 16. That is complete for the stated bound, not a sample.

**Does not:** prove any row is unsolvable. A row could reach `T_16` through an
orbit element of length 17+, or through an orbit BFS deeper than 20, or by an AC
path that never passes near a short trivial pair at all. The test finds
solutions; it cannot certify their absence.

## Recorded alongside

- **AC meet-in-the-middle is budget-bound.** 12 of the 181 shortest minimised
  pairs resolved against `T_16` at fcap 22; all 12 BUDGET at 20M states/row,
  zero hits. Components at cap 22 dwarf any budget that fits in memory. The run
  was stopped rather than ground on for 90 minutes of the same.
- **BFS orbit never beats greedy Whitehead descent.** Over all 2,672 rows: zero
  rows whose orbit contains anything shorter than the greedy minimum. Good news
  for the 1,202-class map, which is built on those minima.
- **No Nielsen class mixes solved and unsolved rows.** Across all 10,115 rows,
  7,815 classes, not one contains both. That is the lift lemma appearing in the
  board data, and it rules out routing any unsolved row via a solved sibling.
- **`ac-03467` at cap 23**: CLOSED, component 158,016,512, depth 381, target not
  in component. Any solution must pass through total length ≥ 24.

## Next lever

The bound that hurt is the ball, not the orbit: elements of length 17–20 were
generated and then discarded, because `T_16` is the largest complete ball the
53 B/state engine holds. `ac_ball_probe_v1.c` drops parent pointers — membership
needs no path — and stores states at ~16–24 B, so a ball roughly 3x larger fits
in the same memory. Path reconstruction is then a separate, much smaller job run
only for the hits.
